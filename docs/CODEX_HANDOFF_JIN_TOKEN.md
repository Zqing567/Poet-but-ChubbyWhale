## 1. 最终核心诉求

这不是“把所有文件挪进一个新仓库”那么简单，而是把**一个已经制作完毕的视频**整理成“别人看得懂、能学习方法、源码可维护、授权范围内可复现、未来作品可复用”的开源项目。

要同时服务三类使用者：
1. **观众/学习者**：打开 README 就能看到视频简介、成片或官方投稿链接（仅使用已核实真实链接）、作品结构图、关键画面与制作方法，不需要翻几百份临时报告。
2. **创作者**：知道图片如何选型、Prompt 如何迭代、为什么海崖由河岸变成悬崖、为什么曲水不是湖、如何搭建角色/心理活动/表情包、配音如何从音色克隆走向朗诵导演谱、字幕与轻动效怎样做。
3. **开发者**：能够找到 Remotion 工程入口、锁定依赖、模块之间的接口、全部运行所需素材、渲染参数与 QA。许可受限时能看到准确缺失依赖与替代方案，不需要碰运气猜路径。

**成功标志：完整的公开说明 + 真实、可维护的制作源码 + 经过权利清点的媒体 + 可复现的构建与验收过程**。不能为了表面上的“100% 复现”偷上传未获授权音轨/角色或伪造完成报告。

## 2. 正确的拆分方法：三个视角 + 一个真实项目工程

作者的 Canvas 按“视觉/听觉”拆；Codex Mermaid 按“声音骨架→海崖→曲水→尾声→合成”，并把字幕、想象气泡、动态表情作为贯穿两幕的视觉层。两者都正确，但服务不同的问题。

新仓库已确定统一采用：
- **叙事（What）**：SC01 显卡海崖（L01～L05），SC02 曲水流饭（L06～L12），END 留白尾声。
- **技术制作（How）**：原诗+句级时间轴、角色与场景资产、朗诵+BGM+音效、像素字幕、气泡/表情/Gemini 或 PNG/WebM 动态、Remotion 合成、4K 发布与 QC。
- **经验与溯源（Why）**：美术参考、候选/最终版本、原图与 Prompt、作者反馈的具体更改、失败方案、可重用做法、版权与素材来源。

**不要把每句、每个场景都拆成重复的独立引擎**：字幕是一套、声音是一套，场景与气泡是其事件/素材实例。代码按稳定“输入→加工→输出→验收”模块划分，文档再按三个视角建立交叉索引。新作品归 projects/<slug>/，复用至少两部的真正通用能力才考虑抽到 shared/，不提前造庞大框架。
