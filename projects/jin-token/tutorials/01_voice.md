# 《将进 token》的配音是怎么做出来的？

这条视频的声音并不是一次生成的。我们先确定大肥鱼的音色，再慢慢调整朗诵的停顿、重音、拖长音和句子之间的衔接。中文诗句还算好处理，混在里面的 **token、Claude、GPT、SOTA** 等英文词反倒经常打乱节奏。

下面按实际制作顺序讲六步。每一步都附上相关提示词或请求文件。如果你打算让 Agent 帮你复刻，直接跳到文末的「交给 Agent 复刻」即可。

## 1. 平台与模型：先生成一句试试

- **平台**：[阿里云百炼](https://bailian.console.aliyun.com/)（[声音复刻教程](https://help.aliyun.com/zh/model-studio/voice-cloning-user-guide)｜[语音合成 HTTP API](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)）
- **模型**：`qwen-audio-3.1-tts-flash`
- **接口示例（北京地域）**：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer`
- **本项目后期试音参数**：WAV、24 kHz、单声道，`rate: 1.0`、`volume: 60`、`seed: 1061`。

项目制作时使用过千问兼容的 HTTP 服务；如果你直接用阿里云百炼，请按自己的地域、业务空间和音色重新填写接口参数。`seed` 是当时保存的请求值，不代表能够百分之百复现相同的朗读。

**先测这一句**：

> 天生用户必有用，token 用尽还复来！

生成后先听两件事：有无漏字、错读；`token 用尽` 是否连贯、`还复来` 有没有不自然的停顿。基本正常，再开始做整段。

## 2. 音色复制：先固定声音，再调整演技

我们采用的是**复刻音色**。实际做法很简单：准备一段清楚、来源许可允许使用的人声参考，调用平台的音色创建接口，得到当前账号下的音色 ID，然后用它生成测试句。

1. 整理参考音频，尽量避免 BGM、多人说话和明显噪声。
2. 按[官方声音复刻接口](https://help.aliyun.com/zh/model-studio/voice-clone-design-http-api)上传参考音频，创建时将 `target_model` 设为 `qwen-audio-3.1-tts-flash`。
3. 用返回的音色 ID 生成测试句。声音满意后就先锁住，不要一边改朗诵、一边反复换音色。

**关于音色素材开源**：我们准备把可合法公开的音色参考文件、试听示例及复刻配置一并整理到项目中，方便大家在自己的账号下重新建立音色。目前这篇教程引用的公开目录**尚未包含已经确认可再分发的完整音色样本**，因此不提供未经审核的原始人声。即使拿到同一份样本，也需要自己创建音色 ID，效果可能有一定差异。

## 3. 朗诵生成：不要一上来就念整首

我们让 Agent 调用 API、保存音频、试听并按反馈改稿。早期使用的基础表演提示词是：

```text
使用参考音色，认真地吟诵古风诗歌。中文清楚，英文术语自然；不要唱成流行歌，不要添加原文外的字。逗号处有气口，句尾完整。
```

它能够确定大致风格，但管不住具体的重音和停顿，所以后面才加入了导演谱。

首轮建议只做三组，像我们当时一样先解决最容易出问题的地方：

| 试听组 | 内容 | 主要听什么 |
| --- | --- | --- |
| G1 | 第1～2句，两次「君不见」 | 两次起兴不能完全一个腔调 |
| G34 | 第6～9句，从邀请到切歌 | 朗诵能否自然收势并接入唱段 |
| G56 | 第11～12句 | 如何从劝充值接到最后两次「token来」 |

可以直接从 [G1_A 真实请求](voice/requests/G1_A.json)开始：生成一版 `G1_A_r01.wav`，试听、记录具体问题，再生成 `r02`。**好的一版先保存，不要覆盖。**

第9句的英文唱段使用了已有歌曲片段，并非让朗诵模型直接唱英文。跟做时使用自己的、或有权使用的唱段即可。

## 4. 提示词与导演谱：让大肥鱼真正会吟诗

只给模型一句「豪迈地朗诵」并不够。后来我让 GPT 网页端研究古诗朗诵的停连、重音、节奏和拖腔，再结合这首诗逐句批注，做出了[完整十二句导演谱](voice/director-score.md)。

例如第一句，我们希望：

```text
君不见 // 用户 token 天上来 / 落入铁盆 / 不复回。

「君不见」由低渐扬；重音落在「天上来」「落入铁盆」；
「来」稍微舒展，最后的「回」自然收住，为下一句留下气口。
```

导演谱里的斜线只是给人和 Agent 看的标记，**不要把这些符号直接扔给 TTS 朗读**。实际生成时，把意思整理成自然语言提示词；接口支持的话，再用 SSML 单独调整某些停顿。

我们给 G1 做过 A/B：

- **A版**：两句自然连续生成。
- **B版**：同一表演方向，增加 SSML 停顿，并对过长静默做后期修整。

当时 G1 使用的表演要求是：

```text
沿用参考音色。像诗会主人对朋友吟诗：第一次君不见开阔庄重、由低渐扬；第二次短些，转为得意炫饭，吃白饭、两碗一碗轻快清楚。词组连贯，收声干净。只读台词。
```

B版的一个节选：

```xml
<speak>
君不见<break time="260ms"/>用户 token 天上来<break time="180ms"/>
落入铁盆不复回。<break time="380ms"/>
君不见<break time="130ms"/>高高在上吃白饭<break time="180ms"/>
招炫两碗暮一碗。
</speak>
```

「招炫」是为了辅助把「朝」读作 *zhāo*，**视频字幕仍是原句**。有些版本还用「羌进」辅助「将进」的读法。合成用文字与画面显示文字，建议始终分开保存。

![G1 A/B 时长对照（示意图，不是音频波形）](voice/g1-comparison.svg)

这一轮 G1 的 A版约 **10.89秒**，B版约 **14.49秒**，最后选了经过静默修整的 B版；但 G34 选择的是 A版。也就是说，**SSML 并不是加得越多越好**。

实际测试还发现：请求 `250ms` 停顿，样本里测出的增量约为 `350ms`；`instruction` 虽然被接口接收，但不代表情绪真的准确改变。用耳朵听最终效果，比把某个参数调到「理论正确」更重要。

完整可复制请求：[G1_A](voice/requests/G1_A.json) / [G1_B](voice/requests/G1_B.json)，批注的结构化版本在[导演谱 JSON](voice/director-score.json)。

## 5. 最后微调：听不满意，就只改那一小段

这里我们主要靠两种办法：**用直白的语言描述具体问题**，以及**对同一句多生成几版再挑**。相同音色、相似提示词也可能产生不同的表现，所以音频生成同样需要「抽卡」。

### 「Claude，GPT」这一句，我们抽了好几轮

开始时英文名称和字母的连读总不自然。我们试过给字母插停顿，也试过中文近音，但都不够满意。后来回到英文原词，沿用先前比较喜欢的表演方向重新生成候选，才选到更合适的读法。

可以学习的不是某个「万能英文发音提示词」，而是：**觉得不对就缩小问题范围，不要把已经满意的整段配音全部推倒重做。** 对应的后续可用请求见 [G34_A](voice/requests/G34_A.json)。

### 「token用尽」突然换气怎么办？

第4句也遇到过英文后断气的问题。后来我们直接写明：

```text
后半句一气呵成，token直接连着用尽说，像普通中英混说一样流畅；重音落在还复来，语气上扬、来舒展。不要在英文后换气或重新起句。只读台词。
```

这次的实际朗读输入是 `天生用户必有用，token用尽寰复来！`，用「寰」辅助 `huán` 的读音，字幕仍然写「还」。最后用普通文本获得了更连贯的结果，不需要硬插 SSML。见 [L04 最终修订请求](voice/requests/L04_natural_connected_r03.json)。

结尾「与尔同销万卡愁」也采用了局部重生成，把「与尔同销」连贯念出，再突出「万、卡、愁」，最后接回选好的音轨。这个过程是**语音生成和音频剪辑**，不是重新训练模型。[结尾修订请求](voice/requests/G56_tail_four_connected_three_stressed_r01.json)

## 6. 把音频接成完整视频

1. **先拼朗诵干声**：选好每组的 WAV，优先在自然气口连接，确认没有截字或音色突变。
2. **补音乐和音效**：朗诵时给背景音乐适当让位，歌曲片段单独处理；金币入盆音效按画面时间点加入。
3. **字幕跟着声音走**：依据选好的声音时间轴安排每句诗，不要把12句平均分配时间。
4. **做好片尾**：最终片尾多保留约3秒动态与BGM淡出，全片为87.1秒。

本项目在部分接缝使用过约8ms交叉淡化，但前提是两侧都有自然静默。具体剪辑方式可以看[工程和验证记录](../editor/README.md)，不必一开始就追求这些参数。

## 如果你也打算让 Agent 复刻

把本页、[导演谱](voice/director-score.md)、[真实请求模板](voice/requests/G1_A.json)与可合法使用的音色参考一起交给 Agent，然后让它按照下面的顺序工作：

1. 在本地核对 **模型、接口、音色 ID 和 API Key 环境变量**。不要把真实密钥写进对话、源码或 Git。
2. 先生成 G1 的 A/B 试听。保存 WAV 和脱敏请求参数；有缺字、错读先修这些客观问题。
3. 用导演谱生成 G34、G56 的少量候选，必要时只修改失败的词句，不允许一次性几十轮刷额度。
4. 把候选按组整理成能快速听的 A/B 清单，**由用户决定哪版表演更好**。
5. 拼出无BGM的完整干声，检查连贯度，再做混音和字幕时间轴。

你可以直接把这句话发给 Agent：

> 参考此教程、导演谱和 `voice/requests/` 下的真实请求，使用我本机合法配置的音色和 API 进行《将进 token》朗诵复刻。先完成 G1 A/B 试听，按导演谱检查停顿、重音与中英连读，保留每轮 WAV 和参数，不要覆盖好版本。只针对失败句子重生成，控制调用次数，最终提供试听对照及一版完整干声。不得更改视频显示稿，不得泄露密钥，也不要宣称拥有未验证的音色/素材许可。

**复刻声音不等于必然复现完全相同的声音波形。** 模型版本、音色复刻结果、随机性、剪辑和混音都会影响最终听感。
