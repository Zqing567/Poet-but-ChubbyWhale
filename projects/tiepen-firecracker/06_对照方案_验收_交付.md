# 视觉方案如何对比、这轮交什么才算真的做完

## 1. 本轮只比较两个关键问题

**先比美术**，不能还没确定画面就精调字幕。两版都应使用同一小汐参考图、同一铁盆、同一工位/院落布置和同一组镜头：
- A：写实摄影感环境 + Q版小汐。参考实景炸盆视频的普通真实空间和小比例角色，这是当前首推路线。
- B：柔和半写实环境 + 同一个Q版小汐。以更温柔协调的材质与调色增强统一感，但不能恢复古风/漫画房间。

可先用 **KF01工位、KF04院落、KF08扣盆** 三张图做A/B并排，实图比口头解释有效。作者选定美术后，才为选定方案补齐关键帧与视频。

**再比字幕**：在不改视频镜头、音效和画幅的前提下做两个叠字样片：
- T-A 右侧诗文：约70～75%画面演戏，25～30%留诗文；如果原场景太挤，可用临时半透明纸面，但不要逼小汐缩成一个小点。
- T-B 底部逐句：不占固定侧栏，按朗诵只显示当前句，一行或两行，视字体实际排版而定。
- T-C 场景融合文字只作附加探索：让诗文出现于屏幕或墙面等，容易和背景冲突，不作为唯一字幕实现。

**先不锁定**最终字幕方案、字幕字体、横竖屏双版。建议样片先16:9，9:16之后单独构图。

## 2. 素材与代码摆放：清楚但不复杂

Codex 根据仓库实际情况建立必要目录即可：

- source/ 或 references/：所使用角色参考、铁盆设定、原始生成提示词及来源说明。第三方《炸盆子》原视频/久留美截图如未获公开授权，留在本机，不推送。
- keyframes/：KF01～KF09 的静帧/首尾帧、同一张盆P0/P1/P2对照图。
- production/：只存本轮真正使用的背景、人物层、道具层、音轨、Remotion工程或已有工程的最小复用文件。
- previews/：A/B对照板、可播放第一节视频；不要提交大批失败试验视频。
- report/：一份简短制作报告，写真实选用画面、声音、已完成镜头、失败和待作者决定的项。

不要一开始为本项目新增通用渲染框架、资产注册系统、复杂多Agent审批系统或到处复制的保险配置。优先从《将进 token》复用 Remotion/字幕/音频剪辑成熟方法，改动必须服务当前第一节。

## 3. 实际验收（必须看画面）

| 检查点 | 实际可观察标准 |
| --- | --- |
| 风格 | 工位和院落有真实或半写实质感，无古风装潢与卡通背景；小汐仍是原二次元Q版 |
| 镜头距离 | 多数是中远景，人物与现实道具空间清楚；只有扣盆反应镜头略近 |
| 小汐形象 | 发型、脸、呆毛、服装、头身比例跨镜头一致，没有突然长大/变脸 |
| 铁盆一致性 | P0→P1→P2同一只盆、同一处沿凹痕、同一破洞位置和方向、同一相对尺寸 |
| 诗意与剧情 | L01疲惫→L02盖盆/退开→L03盆飞/底破/铁片→L04扣头/呆毛→L05铁片消失，各自能看懂 |
| 转场 | 抱盆跑动时切换场景，没有不必要的点火/跑路过程；飞盆时先天上再回院落 |
| 两个笑点 | “盆飞到天上”与“飞回扣头”都清晰，而且第二个笑点留出了反应 |
| Claude梗 | 用Claude形象重新制作「老实编程，很枯燥吧」心理气泡，别拿原截图直接铺画面 |
| 声音 | 先试听五句导演谱、按真实音频剪辑；音效可听但不盖字，字幕在下一轮对照 |
| 真实成果 | A/B风格能并排看、至少一版第一节可播放；不是只有计划书和模型提示词 |

实际提交前检查输出的真实分辨率/画幅、关键帧渲染截图、转场前后、盆扣头一帧、首节音视频是否可播放、是否有无意义黑帧/突兀音频截断。低影响改动不需要以全仓海量测试代替这些视觉验收。

## 4. 希望作者点开就能看的交付

1. **A/B风格对照板**：KF01、KF04、KF08各2张，同框对比并标明 A/B，方便确认美术路线。
2. **同一只盆的P0/P1/P2状态图**：无字可读，能直观看到洞口和盆沿相对关系。
3. **第一节粗剪 animatic（有真实可用音轨更好）**：即使关键动作尚为静帧也应能一遍看懂五句，标清这是粗剪。
4. **第一节正式视觉样片**：优选美术风格，16:9，可播放，五句动作按朗诵到位。尽量通过真实生成与合成完成；受实际接口/授权阻塞时要说清楚，不能靠空文件伪交付。
5. **字幕比较截图或短片**：等主体视觉确认之后才制作，不要抢在前头定风格。
6. **制作报告**：用几段中文说清做了什么、哪版好、哪里还需要汐汐/作者决定、哪种工具被真正调用过，附关键帧和视频入口以及远端提交链接。

优先保证视觉样片和人物/铁盆一致性；不是为了凑文件数量而堆报告、证明文件或复杂测试。

## 5. 收口边界

到首节样片通过必要检查后停下，等作者确认整体视觉风格。即使余汐已经讨论过其他三节，也**不要自动启动第二、三、四节的制作**。原诗及开发日志不改，其他旧作品不动。可在自己的任务分支 push 提供作者审核；是否合并 main 以项目实际习惯和作者本轮指令为准。

同时注意仓库为公开仓库：原参考视频、久留美原截图、未经明确授权的外部形象/歌曲不因个人能观看而自动适合重新上传。你可以将这些原件放本地引用，项目公开版保留你制作的新画面、Prompt、可用素材和来源说明。
